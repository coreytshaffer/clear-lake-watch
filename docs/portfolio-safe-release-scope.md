# Portfolio-Safe Release Scope

Status: recommended next fork before live feature expansion

Date: 2026-05-05

This scope defines a conservative release target for presenting Clear Lake Watch as a professional portfolio artifact. It is not a public launch plan and does not authorize staging, committing, pushing, or broad promotion by itself.

## Goal

Make Clear Lake Watch presentable as a flagship systems-integration artifact while preserving the boundary that it is a late prototype / early MVP, not an official monitoring authority.

## Include

- live dashboard mirror or local dashboard link
- README front door
- methodology page
- project page
- publication review checklist
- portfolio case study
- internship share brief and career-services call notes
- local screenshot review artifacts
- validation status from the latest dashboard check
- clear public/private boundary notes

## Avoid

- claims of official monitoring authority
- broad community launch language
- public-health advisory language
- live field submission workflow
- deployed field-sensor claims
- validated forecast claims
- experimental AI promotion

## Screenshot Targets

Capture or prepare screenshots for:

- dashboard hero and live snapshot
- map trust filter and site-registry QA
- methodology disclaimer or signal-type explanation
- publication checklist or validation evidence, if useful

Screenshots should support the case study, not imply a fresh public launch unless the publication checklist has passed.

## Soft-Share Audience

Use private feedback first:

- SNHU advisor
- career services
- one trusted environmental or water-quality contact

Ask for feedback on:

- clarity
- professionalism
- public-health wording
- whether any claim feels overstated
- whether the project reads as a prototype rather than an authority

## Next Technical Fork

After the portfolio-safe release pass, choose between:

- site-registry trust hardening
- reviewed weather telemetry integration

Recommendation: do real site review before live weather telemetry.

Reason: site-registry trust is already part of the public dashboard's current credibility boundary. Weather telemetry expands the system surface and should wait until the current public trust layer is tighter.

## Decision Rule

If the goal is portfolio readiness, polish evidence and trust boundaries before adding new live data surfaces.

If the goal is system expansion, only proceed after the portfolio-safe release scope is either completed or intentionally deferred.
